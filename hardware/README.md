# Hardware configuration

Files to deploy next to a real table (`TABLE_MODE=hardware`).

**Setting this up for the first time? Follow [`GUIDE-EQUIPE-DUBAI.md`](GUIDE-EQUIPE-DUBAI.md)** (in French,
step by step, with a "validated when" check at every step). How each test level works and what
it must show: [`TESTING.md`](TESTING.md).

| File                             | Runs on        | Goes to                                                        |
| -------------------------------- | -------------- | -------------------------------------------------------------- |
| `broker/acl`                     | MQTT broker    | `/mosquitto/config/acl` (single source for every setup)        |
| `broker/mosquitto.conf`          | MQTT broker    | `/mosquitto/config/` (+ `passwd`, TLS certs): TLS-direct setup |
| `table-agent/agent.example.yaml` | Raspberry Pi 5 | `/etc/athar/agent.yaml` (replace `REPLACE_WITH_TABLE_ID`)      |
| `board/config.yaml`              | MKS DLC32      | FluidNC (sent with FluidTerm, see the guide, step E3)          |
| `pi/setup-pi.sh`                 | Raspberry Pi 5 | run once over SSH: Docker, GitHub CLI, serial/MQTT tools       |

Three broker setups share the same `broker/acl`:

- **On-site test (current plan)**: `deploy/docker-compose.local.yml` with `deploy/mosquitto/mosquitto.local.conf`
  (plain MQTT on 1883, API and broker on the Pi). See the guide.
- **Google Cloud test stack** (paused, not deleted): `deploy/docker-compose.yml` puts Mosquitto behind Caddy
  (`wss://mqtt.<domain>`, `deploy/mosquitto/mosquitto.conf`). See [`../deploy`](../deploy/README.md).
- **TLS-direct broker**: `broker/mosquitto.conf` terminates TLS itself (`mqtts://…:8883`) and also
  opens a `1883` listener on localhost for development.

Facts that do not change between setups:

- The MQTT username of a table **is its table id** (the ACL scopes it with `%u`). The id is generated by
  `table-create` or by `POST /api/v1/admin/tables/provision`, which returns exactly that username.
- API login: user `athar-api`; set `MQTT_URL`, `MQTT_USERNAME`, `MQTT_PASSWORD` for the API
  (`apps/api/.env`, or `deploy/.env` with Docker).
- Create broker users with `mosquitto_passwd` (`-c` only for the first one), then give `passwd` to user 1883:
  `sudo chown 1883:1883 passwd && sudo chmod 600 passwd`, after every change.
- The `presence` payload is the plain text `online` / `offline` (not JSON), including the Last Will.
- `apps/table-agent` (the Raspberry Pi program between the broker and the board) is **not written yet**.
